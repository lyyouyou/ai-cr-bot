# 前端团队代码规范（RAG 检索素材示例）

> 这份文件就是"RAG 知识库"里的一条资料。评审时系统会根据改动内容，
> 把和本次相关的段落自动挑出来塞进给模型的 prompt，让模型按"你们家规矩"评审，
> 而不是按通用感觉评审。

## 状态管理
- 统一使用项目封装的 `useRequest`（src/hooks/useRequest.ts）处理请求，禁止在组件里裸写 fetch/axios。
- 异步 loading 必须在 finally 里复位，不能只在成功路径关闭。

## 空值与类型
- 访问深层对象前必须判空，推荐可选链 `a?.b?.c`，禁止不判空直接解构深层属性。
- 接口返回可能为 null 的字段，使用前要兜底，禁止把 null 直接传给子组件必填 prop。

## 交互防重复
- 提交类按钮点击后必须进入 loading 禁用态，防止用户重复点击导致重复提交。
- 搜索、输入联想必须做防抖（debounce 300ms）。

## 安全
- 禁止使用 `dangerouslySetInnerHTML` 渲染任何用户可控内容；富文本必须先经白名单消毒。
- 密钥、token、内网地址禁止写进前端代码和提交记录。

## 性能
- 长列表（超过 50 行）必须使用虚拟滚动，禁止一次性全量渲染。
- 事件监听、定时器必须在 useEffect cleanup 里清理，避免内存泄漏。
